# UI | واجهة المستخدم

Product UI conventions distilled from real feedback. Stack specifics (Angular) are
in `stacks/angular`.

## Arabic-first, direction flips with language | العربية أولاً والاتجاه يقلب

RTL is the primary layout; design for future languages (FR/ES/DE). When the
language changes, **arrows, alignment, and button sides flip** — an arrow points
and sits on the correct side per direction (a recurring bug). All user-visible
strings come from the project catalog (both `ar` and `en`), never hardcoded; a
missing key shows as a raw symbol to the user.

## Per-screen checklist | قائمة فحص لكل شاشة

- **Four states:** empty / loading / error / full — each designed.
- **Field alignment:** inputs and their helper notes aligned; no field higher than
  its neighbor (a repeated defect across screens).
- **A11y:** keyboard + focus order, contrast WCAG AA, screen-reader labels;
  respect an Accessibility Profile where the product has one.
- **No dead control:** every visible control does something (an opt-in row-size
  select shipped dead on 11 screens — do not ship half-wired controls).
- Assert what a person can reach, not what the DOM has (a clipped `thead` is
  "visible" to the DOM but unreachable).

## Recurring conventions | أعراف متكررة

- **Every list:** server-side pagination (`skip`/`take`), sortable, optional
  page-size select; page numbers in a fixed run that adapts to width; return to
  default paging state on re-entry.
- **After save:** return to the previous screen.
- **Errors:** toast/notification system, not an in-page bar; an error that must
  persist does not auto-dismiss.
- **"All of the above" / "none of the above"** answers are always last when
  options are shuffled.
- **Pickers:** multi-select dropdown with search; show items from the start and
  grow (don't require a search to see the first ones).
- **Modals** for add/edit where it fits; sized to match the inputs.
- **Footer** sits at the bottom regardless of page height.
## Responsive is a standard, not a check | الاستجابة معيار لا فحص

Design the **narrow** layout first; the wide one is the narrow one with room.

- **Container queries over window-width rules** wherever the layout has a fixed
  sidebar — the window is not the space the content has. A window rule once fixed
  768 and broke 1024×768 (iPad landscape), and another hid icons on iPad mini.
- **Deliberate columns over `auto-fit`.** `repeat(auto-fit, minmax(…))` lets the
  viewport decide which field pairs with which, so the field somebody types first
  ends up beside a dropdown at one width and alone at another.
- **`align-items: start` on any field grid.** A stretched grid centres a short
  field in a tall neighbour's row — the "a field higher than its neighbour"
  defect in its silent form.
- Test at **real device sizes**, both orientations, and never only at the widths
  the breakpoints name.

## Interactive: the screen answers | التفاعل أن تُجيب الشاشة

Every action acknowledges itself. A control that does nothing for 300 ms reads as
broken before it reads as slow.

- **Pressed states move** (`-translate-y-[1px]` or `scale(.98)`); a saving button
  says it is saving rather than freezing; a list says what changed after it
  changes.
- **Motion carries meaning or it is noise.** Use it to show where something came
  from or went — a panel opening from the control that opened it, a row settling
  after it moves. Never a loop, never decoration, and **honour
  `prefers-reduced-motion`** every time.
- **An empty screen is an invitation, not a mood**: what is true, and the one
  thing to do about it. A grid drawn over nothing says nothing several times.
- **No dead air on a boundary:** loading has a shape (skeleton matching the final
  layout, not a spinner), failure says what to do, success is visible.

## Beautiful is restraint executed precisely | الجمال انضباط مُتقَن

The identity is already decided in the tokens (`90-design.md`). Beauty comes from
spacing on one scale, type on one scale, alignment that never breaks, and one
idea per screen — **not from adding**. Before shipping a screen, remove one thing.

**Skills, invoked before the design and not after being asked:** `ui-ux-pro-max`
(dense product UI), `frontend-design` (the writing and the empty states),
`make-interfaces-feel-better` (motion and feedback), `design-audit` /
`web-design-guidelines` (review). `design-taste-frontend` excludes dashboards and
data tables — do not reach for it here.
