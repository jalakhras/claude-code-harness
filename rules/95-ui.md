# UI | واجهة المستخدم

Product UI conventions distilled from real feedback. Stack specifics (Angular) are
in `stacks/angular`.

## Arabic-first, direction flips with language | العربية أولاً والاتجاه يقلب

RTL is the primary layout; design for future languages (FR/ES/DE). When the
language changes, **arrows, alignment, and button sides flip** — an arrow points
and sits on the correct side per direction (a recurring bug). All user-visible
strings come from the project catalog (both `ar` and `en`), never hardcoded; a
missing key shows as a raw symbol to the user.

## Per-screen checklist | قائمة فحص لكل شاشة

- **Four states:** empty / loading / error / full — each designed.
- **Field alignment:** inputs and their helper notes aligned; no field higher than
  its neighbor (a repeated defect across screens).
- **A11y:** keyboard + focus order, contrast WCAG AA, screen-reader labels;
  respect an Accessibility Profile where the product has one.
- **No dead control:** every visible control does something (an opt-in row-size
  select shipped dead on 11 screens — do not ship half-wired controls).
- Assert what a person can reach, not what the DOM has (a clipped `thead` is
  "visible" to the DOM but unreachable).

## Recurring conventions | أعراف متكررة

- **Every list:** server-side pagination (`skip`/`take`), sortable, optional
  page-size select; page numbers in a fixed run that adapts to width; return to
  default paging state on re-entry.
- **After save:** return to the previous screen.
- **Errors:** toast/notification system, not an in-page bar; an error that must
  persist does not auto-dismiss.
- **"All of the above" / "none of the above"** answers are always last when
  options are shuffled.
- **Pickers:** multi-select dropdown with search; show items from the start and
  grow (don't require a search to see the first ones).
- **Modals** for add/edit where it fits; sized to match the inputs.
- **Footer** sits at the bottom regardless of page height.
- Responsive at real device sizes (a bug hid icons on iPad mini 768×1024); prefer
  container queries over window-width rules where the layout has a fixed sidebar.
